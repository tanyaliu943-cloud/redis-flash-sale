# 超市限量商品搶購系統｜專題規劃與開發紀錄

> 可直接貼到 Notion 的專題紀錄草稿。雲端和 GitHub 連結待完成後補上。

## 專題概述

以日常超市熱門促銷品為情境，模擬多人同時搶購有限庫存時的下單、付款保留、候補遞補與補貨流程。顧客可一次選多項商品，送出後各商品各自建立訂單與處理狀態。

## 動機與預期目標

熱門促銷商品常遇到多人搶購、庫存有限的情況。為避免超賣與重複訂單，並公平處理候補與逾時釋出的庫存，專題運用 Redis 模擬限量搶購流程。

- 顧客可將多種商品放入購物車，各品項獨立建立訂單。
- 以 Redis 管理庫存、限購、付款期限和 FIFO 候補。
- 記錄訂單事件，並觀察背景工作者處理與通知流程。

## 系統架構與技術

- Python、Streamlit：使用者介面與應用流程。
- redis-py、Redis／Valkey：資料存取與進階資料結構操作。
- `app.py`：搶購、店員管理、訂單分析與自動期限／補貨檢查。
- `worker.py`：Streams Consumer Group 背景事件處理、重試、Dead Letter 與 Pub/Sub。
- `import_open_data.py`：建立 10 項展示商品資料。
- `redis_config.py`：本機與雲端 Redis 連線設定。

## Redis 功能與用途

- Hash：商品及訂單欄位。
- String Counter：每位顧客購買某商品的數量。
- List：FIFO 候補佇列。
- Sorted Set：付款與補貨期限。
- Set：依商品、狀態、顧客建立訂單索引，支援彙總查詢。
- Lua：將單項商品的庫存、限購、建單、候補與索引操作整合執行。
- Transactions、Pipelines：維護多步驟更新一致性並批次查詢。
- Streams Consumer Group：分派背景事件、確認、重領與失敗隔離。
- Pub/Sub：背景工作者完成處理後即時發布商品通知。

## 開發階段與成果

1. **題目與資料模型**：規劃限量商品、顧客、購物車、獨立品項訂單、候補與期限資料。
2. **單品流程**：完成庫存扣減、限購檢查、待付款訂單、取消與 FIFO 遞補。
3. **多商品購物車**：可一次選擇多項商品；每個品項分別建立訂單並處理付款或候補狀態。
4. **Lua 與冪等處理**：以 Lua 原子檢查和更新單一商品訂單資料；使用冪等鍵避免相同購物車品項重複扣庫存。
5. **管理與分析介面**：加入店員模擬付款／取消、顧客訂單查詢、狀態篩選與營運摘要。
6. **事件背景處理**：以 Streams 保存事件，工作者使用 Consumer Group 消費；成功事件寫入通知 Stream 並透過 Pub/Sub 發布。
7. **模擬補貨**：低庫存時建立到貨期限；到貨後增加模擬庫存並依 FIFO 遞補。
8. **公開準備**：已加入依 `REDIS_URL` 連線、Python 依賴清單和秘密排除規則；GitHub 公開 repository 與雲端服務仍待帳號連線和部署確認。

## 操作流程

1. 顧客選擇代號，將一項或多項商品放入購物車並設定數量。
2. 送出購物車；每項商品獨立檢查限購、庫存與候補狀態。
3. 有庫存的品項建立待付款訂單；缺貨或已有排隊者的品項加入 FIFO 候補。
4. 店員可模擬付款或取消；取消／逾時會釋放庫存並處理候補遞補。
5. 低庫存觸發模擬補貨；頁面開啟期間每 5 秒檢查付款與補貨期限。
6. Worker 處理 Stream 事件，更新通知 Stream 並透過 Pub/Sub 廣播。
7. 訂單分析頁面用索引統計狀態和金額，並顯示近期事件。

## 實際操作證據

目前使用者截圖已呈現多商品購物車送單、各商品獨立訂單、店員付款與取消、Streams Worker 收到 `order_created`／`payment_confirmed`／`order_cancelled`／`order_expired`，以及訂單分析介面。正式簡報可放操作介面與 Worker 記錄截圖。

## Open Data 與模擬資料

Open Food Facts 提供部分商品名稱、條碼和 Nutri-Score；商品售價、庫存、每人限購與補貨數量為專題模擬值。其他商品也以模擬資料標示。完整來源見 [`data/open_data_sources.md`](../data/open_data_sources.md)。

## 成果與限制

系統完成多品項獨立下單、庫存／候補／期限管理、付款與取消模擬、背景事件處理和營運分析。付款、供應商與補貨皆為展示模擬；頁面關閉時，Streamlit 內的付款逾期與補貨檢查不會持續執行。雲端公開部署尚未完成，並需另配置 Redis 與常駐背景工作者。
